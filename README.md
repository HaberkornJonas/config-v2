# config-v2

`config-v2` is the bootstrap repository for bringing up an Arch Linux development machine (WSL or VM) from a local checkout.

## Linux Quick Start

Install Git manually first, then clone this repository and run the Linux bootstrap from the local checkout:

```bash
# Arch
pacman -Syu
pacman -S git
```

```bash
git clone https://github.com/HaberkornJonas/config-v2.git
cd config-v2
chmod +x ./setup.sh
./setup.sh
```

`setup.sh` carries its bootstrap configuration inline. If you need different values in your own copy or fork, update the configuration block at the top of `setup.sh` before you run that variant.

`setup.sh` reads `packages/arch.txt` from the same checkout. Running the script from the cloned repository is the supported bootstrap path.

### What the Linux bootstrap does

The Linux entry point is `setup.sh` in your local checkout. The script then:

1. loads the bootstrap configuration declared at the top of the script
2. checks that the host is Arch Linux and installs packages from `packages/arch.txt` in this repository
3. prepares stateful assets (fnm, zsh as login shell, SSH key) without overwriting any that already exist
4. runs `chezmoi init --apply` to apply your user configuration from the separate dotfiles repo

## Path Ownership

Every path the bootstrap touches has exactly one owner: chezmoi rewrites managed paths on every run; `setup.sh` creates stateful assets only when they are missing and never overwrites them.

| Path | Category | Rule |
| --- | --- | --- |
| `~/.zshrc` | chezmoi-managed | Rewritten from `dotfiles/dot_zshrc` on every apply |
| `~/.gitconfig` | chezmoi-managed | Rendered from `dotfiles/dot_gitconfig.tmpl` with the identity values in `setup.sh` |
| `~/.config/starship.toml` | chezmoi-managed | Rewritten from `dotfiles/dot_config/starship.toml` |
| `~/.config/nvim/init.lua` | chezmoi-managed | Rewritten from `dotfiles/dot_config/nvim/init.lua` |
| `~/.config/tmux/tmux.conf` | chezmoi-managed | Rewritten from `dotfiles/dot_config/tmux/tmux.conf` |
| `~/.config/chezmoi/chezmoi.toml` | chezmoi-managed | Regenerated by `chezmoi init` from `dotfiles/.chezmoi.toml.tmpl` on every run |
| `$SSH_KEY_FILE` (default `~/.ssh/id_rsa` and `.pub`) and `~/.ssh/` | stateful-asset | Generated once if missing (`~/.ssh` created with mode 700); never overwritten |
| `~/.gnupg` (GPG keyring) | stateful-asset | Only checked for the configured fingerprint; never written by `setup.sh`; import keys manually |
| `~/.local/share/fnm` (fnm and installed Node versions) | stateful-asset | fnm installed once if missing, with `--skip-shell` so the installer never edits shell startup files |
| Login shell (your `/etc/passwd` entry) | stateful-asset | Changed to zsh via `sudo chsh` only when it is not zsh already |
| `~/.local/share/chezmoi` (legacy chezmoi source) | stateful-asset | Reported, never modified or deleted |

`~/.ssh/config` is not listed: it stays yours, and neither `setup.sh` nor chezmoi writes it. Shell history and zinit plugins are created by zsh at runtime, not by the bootstrap.

## Architecture Overview

This project follows a strict two-repo model:

- `config-v2` owns bootstrap orchestration, inline bootstrap configuration, and package manifests
- the dotfiles repo owns user configuration managed by chezmoi

That split keeps bootstrap orchestration in this repo while letting `setup.sh` delegate user configuration application to chezmoi.

Branches that locked the trunk
by user

Single entry point won immediately: the setup should begin with clone and one script, with no pre-decisions demanded from the operator.

by coach

Conflict detection forced a serious pivot: if the repo overwrites dotfiles, it needs state memory. chezmoi emerged as the clean answer instead of inventing a merge engine.

decision

The split into two repos made the tree stable: install orchestration lives apart from evolving personal dotfiles.

Every concern got an owner. The winning setup stopped trying to make one script control the whole world.

4. Persona Journey

A future self lands on a blank machine and tries to reconstruct what to do without remembering the conversation.

Cold start path

Arrival: "What do I run first?"

The strongest answer remained brutally short: clone the public repo and run setup.sh. The single-entry philosophy is not just convenience; it is orientation.

Calibration: "Do I edit something before the run?"

The shared config file became central because it answers this question. The final synthesis points toward config.sh pre-filled enough to allow a fully silent bootstrap.

Patience: "How long does this take, and when is it done?"

The session exposed a UX gap: a new machine needs signals about duration, first-run expectations, and what remains manual even after automation finishes.

Edge of automation: "Why does my prompt still look wrong?"

Because fonts live on the host side. The post-install checklist exists to keep these off-machine concerns visible instead of burying them in frustration.

Long tail: "When I tweak dotfiles, what habit keeps this system alive?"

The journey surfaced one soft requirement: remember to push dotfile changes. Minimal docs were accepted, but the workflow still needs that maintenance reflex.

5. The Stateful Ghost

An invented technique. Every new environment is haunted by what the old one forgot to confess.

Haunting turned checklist
👻

"I only break on fresh machines."

The ghost names the missing state: variables not written down, packages installed once and never recorded, host-side steps that never made it into code, keys that should not be overwritten, and local dotfile edits that vanish during updates.

  • haunt::missing-vars → solved by a shared config file
  • haunt::forgotten-packages → solved by distro-specific package manifests
  • haunt::destroyed-local-dotfiles → solved by chezmoi state + merge behaviour
  • haunt::host-fonts-and-terminal → solved by post-install checklist
  • haunt::secret-clobbering → solved by non-destructive handling for keys

What the ghost forced into the design

by user

Keep existing SSH key material if present; the script must not smash secrets just because it can.

by coach

State memory is not optional if updates can touch local config; either store hashes, use symlinks, or bring in a real tool.

decision

chezmoi became the anti-haunting device. setup.sh stays small because the ghost scared responsibility boundaries into place.

6. Scenario Cross

Four futures, one architecture. If the plan only works on a lucky day, it is not reproducible.

Arch/Ubuntu × cold/incremental
Arch × cold clone

Minimal machine, minimal assumptions

Anything requiring jq or Python too early is suspicious here. config.sh survives because it can be sourced directly, while fnm via curl keeps Node setup light. Arch-specific package names justify a dedicated package file.

Ubuntu × cold clone

Friendly base, awkward extras

Ubuntu is easier until Docker and .NET need extra repository setup. The architecture still holds because setup.sh orchestrates distro-specific prep instead of hiding it behind fake uniformity.

Arch × incremental sync

Fast-moving box, local edits at risk

This is where naive overwrite strategies fall apart. chezmoi wins the quadrant by remembering deployed state, while the script can rerun as an update/sync tool without pretending it owns user content.

Ubuntu × incremental sync

Stable machine, drifting config

The same split still wins: package manager for installs, chezmoi for dotfiles, manual checklist for host items. A plan that survives all four quadrants is the one that became the session's final architecture.

Climax: Synthesis & key decisions

The brainstorm stopped being a pile of ideas when maintenance pressure, fresh-machine pressure, and public-repo pressure all pointed to the same answer.

Merge commit

Final synthesis

config.sh pre-filled enough for silence, chezmoi as the stateful dotfile owner, and a light-touch setup philosophy that refuses to globalise project-specific clutter. The long-term strategy is not more automation at any cost — it is tighter boundaries.

Highlighted final architecture

The part worth reopening: the buildable shape that emerged from all six techniques.

Blueprint

Two repos, one ritual

The public config system stabilised around a clean split. One repo knows how to prepare the machine. The other knows what the shell, editor, tmux, and prompt should become.

repo: config-v2

config-v2/
├─ setup.sh
├─ config.sh
├─ packages/
│  ├─ arch.txt
│  └─ ubuntu.txt
└─ post-install checklist
setup.sh

Top-level config block, no prompts, silent by default, rerunnable as sync/update, non-destructive for secrets, overwrite-oriented for config.

config.sh

Shared KEY=value truth, parseable without jq or Python, readable from bash and PowerShell.

packages

Distro-specific manifests absorb naming drift and Ubuntu-specific repository setup for tools like Docker and .NET.

repo: dotfiles

dotfiles/
└─ chezmoi-managed state
   ├─ zsh config
   ├─ nvim config
   ├─ tmux config
   ├─ Windows Terminal config
   └─ PowerShell profile
chezmoi

Owns conflict detection, state memory, machine-specific templating, and apply behaviour.

run_once

tpm bootstrap can live in a chezmoi run_once script; lazy.nvim self-bootstrap stays in init.lua.

zsh stack

zinit + zsh-autosuggestions + fast-syntax-highlighting + fzf-tab + zoxide + starship.

Runtime spine: single entry via setup.sh → distro package install → fnm bootstrap → chezmoi init --apply → shell/editor/tmux land in place → post-install checklist catches host fonts and similar edges.

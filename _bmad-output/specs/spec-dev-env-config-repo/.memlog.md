- (note) source: _bmad-output/brainstorming/brainstorm-dev-env-config-repo-2026-08-04/brainstorm-intent.md (fully absorbed)
- (decision) Why: developer wastes manual time re-configuring environments across WSL/VM machines; goal is one-command reproducible setup with ongoing sync support
- (capability) CAP-1: user can bootstrap a fresh Linux (Arch or Ubuntu) dev environment from zero via a single curl one-liner that runs chezmoi init --apply; success: fresh machine reaches fully configured state without manual intervention
- (capability) CAP-2: user can apply and sync dotfiles across machines via chezmoi; success: same dotfile state is reproducibly applied on any registered machine
- (capability) CAP-3: user can re-run setup to update/sync an existing environment (idempotent); success: re-run succeeds without errors and reflects latest config state, never clobbering existing SSH keys or secrets
- (capability) CAP-4: user can bootstrap a Windows companion environment via setup.ps1 using Scoop and winget; success: Windows machine installs the defined tool set without manual steps beyond running setup.ps1
- (constraint) public repo: no secrets stored; only safe references (e.g. GPG key fingerprint) are permitted
- (constraint) Linux-first: WSL/VM on Arch and Ubuntu are the primary targets; per-distro package manifests (packages/arch.txt, packages/ubuntu.txt) required due to material differences
- (constraint) same Git identity across machines
- (constraint) setup must be fully silent/non-interactive once config.sh is prepared; config.sh (KEY=value) is the single source of truth for scripts
- (constraint) non-destructive for secrets/stateful assets: existing SSH keys must be preserved on re-run
- (constraint) ownership model: package managers own software installs; chezmoi owns dotfiles, templating, and conflict/state handling; setup.sh/setup.ps1 orchestrate only; host-only concerns (e.g. Nerd Fonts) live on a post-install checklist outside the repo
- (constraint) two-repo split: config-v2 holds bootstrap/setup logic and package installation; dotfiles repo holds all user config managed by chezmoi
- (constraint) always overwrite managed config on apply (no soft merges for repo-owned files)
- (constraint) no global npm packages; project-specific tools stay in project repos
- (decision) non-goal: full Windows/WSL2 auto-bootstrap through Linux user creation
- (decision) non-goal: Ansible-based provisioning
- (decision) non-goal: YubiKey-backed SSH as a required path for initial setup
- (decision) non-goal: secrets storage in repo beyond safe references
- (decision) non-goal: Mac support (future evaluation item only)
- (assumption) assumed zsh is the target shell on all Linux machines; no alternative shell support required
- (assumption) assumed single developer / single Git identity use; multi-user scenarios not in scope
- (question) open: YubiKey SSH bridge in WSL/VM — future evaluation, not blocking
- (question) open: CI coverage beyond Ubuntu — mentioned as future item, no current requirement
- (question) open: Mac support path — mentioned as future evaluation, no current design requirement
- (decision) tech stack catalog is load-bearing and too broad for kernel constraints; routing to stack.md companion
- (decision) success signal: fresh Arch or Ubuntu machine reaches fully configured usable dev environment via one curl command + chezmoi apply, without manual steps, without destroying existing SSH keys or secrets
